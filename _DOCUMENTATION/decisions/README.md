# Architecture decision log

ADR-017, adopted 2026-11-04 at the owner's explicit request: keep configuration inline in Program.cs; move all sample data to static Data/DatabaseSeeder.cs, called with a scoped AppDbContext after inline Development MigrateAsync. Remove both EF seed callbacks and their duplicated bodies. Preserve seed data/parent-first ordering and rerun behavior; no DI seeder abstraction, initializer mode, new settings or schema migration. This supersedes earlier inline-seeding/no-seeder requirements, including that portion of ADR-016. [Implementation and verification](../features/LOCAL_DEVELOPMENT.md).

ADR-016, adopted 2026-11-04: native AppUser -> UserRole -> Role -> RoleSystemFeature -> SystemFeature models implement database-backed permissions. Explicit feature policies and one generalized requirement/handler read current grants on each request; multiple roles contribute a union, multiple policies require all grants. No Identity role framework, dynamic policy provider or permission claims in cookies. Inline Program.cs owns registrations and mirrored initialization; existing grants are preserved. [Implementation and recovery](../features/ROLE_PERMISSIONS.md).

2026-11-03 ADR-015 supersedes ADR-012's folder-only-root/backend-only knowledge layout: root AGENTS.md is the project entry; shared maintained Markdown/assets live in _DOCUMENTATION with question routing and central scope guides. Backend solution/SDK/tool manifests and all application/data locations remain unchanged. See [repository map](../REPOSITORY_MAP.md) and [agent workflow](../features/AGENT_WORKFLOW.md).

2026-11-02 highest-priority owner preference: beginner-readable built-in configuration and both EF seed callbacks inline in Program.cs; never extract options/seed setup into functions/classes/files. Keep only needed settings. Default SQL retries/MVC CSRF/cookie fixes and parent-save-child seeding are the accepted minimum; all 34 backend tests pass. This supersedes older no-seeding/failed-startup notes.

2026-11-02 owner direction supersedes Identity: plain AppUser, ordinary DbContext, one model per named .cs file. Native salted PBKDF2 hashing plus standard cookie auth replaces manager/role/token-provider setup. Preserve passwords/account relations with a reviewed migration; retain historical migration history and unmapped metadata archives for data recovery.

2026-11-02 owner direction: minimal startup with no custom header/hub middleware, explicit key-persistence block or partial Program class. Remove SignalR for now; messages use authorized REST send/history with simple browser refresh. Tests use existing AppDbContext to locate the application assembly.

2026-11-02 latest owner configuration direction: use standard appsettings.json with GetConnectionString("DefaultConnection") and direct configuration key access. Remove API .env parsing, secret aliases/SQL construction, demo seeding and initializer mode. Docker Compose retains its own private credentials; application C# remains inline in Program.cs.

2026-11-02 owner override to ADR-013 startup style: keep all startup settings and middleware directly in `Program.cs` with inline callbacks; no named setup methods or separate configuration-only C# classes. Explicit methods and named transaction operations remain preferred elsewhere. EF tooling uses the same application host.
