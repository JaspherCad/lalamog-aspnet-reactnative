# Active backend scope

Startup must obey the [mandatory owner rule](../../AGENTS.md#mandatory-owner-rule-basic-setup-inline-in-programcs): basic built-in configuration inline in Program.cs, without configuration wrappers or extra settings. Owner revision 2026-11-04 places seed data in static Data/DatabaseSeeder.cs, called with the scoped AppDbContext after Development MigrateAsync; no duplicated EF seed callbacks or seeder DI abstraction. Seeding stays parent-first, repeatable and preserves edits. Standard Git-ignored appsettings.Development.json may hold local SQL values.

Current style/structure: [backend structure](../features/BACKEND_STRUCTURE.md). Use explicit constructors/method bodies, inline startup callbacks in `Program.cs` and no configuration-only C# files; elsewhere no authored arrow/lambda syntax, interface-based service injection, one interface per `Interfaces/` file and property-based request/response classes in DTOs/. Domain models each have their own Models/*.cs file; AppUser is a plain class and AppDbContext derives directly from DbContext. No ASP.NET Identity services/base classes. Preserve the horizontal single-project N-tier structure and generated migration files.

Read repository [AGENTS.md](../../AGENTS.md) first, then [CODEX_BOOTSTRAP.md](../CODEX_BOOTSTRAP.md) and its required sequence, [API contracts](../API_CONTRACTS.md), [data model](../DATA_MODEL.md), and relevant [backend backlog](../backlogs/BACKEND.md)/[feature guide](../features/README.md). Every feature implementation/fix/refactor must automatically update its guide, or create/register one for a new feature, and refresh handoff under [the memory protocol](../memory/PROTOCOL.md) before completion.

Preserve controllers → services → domain repositories, authenticated actor identity, membership rules, CSRF cookies, retriable serializable work and SQL structural constraints. Both `Migrations/` and `Data/Migrations/` belong to active AppDbContext. Use appsettings.json with ConnectionStrings:DefaultConnection. No API .env loader or initializer mode. Development startup calls MigrateAsync and static DatabaseSeeder.SeedAsync in one short scope before requests. Compose up plus API startup rebuilds a fresh local database; other environments use explicit migrations without automatic demo seeding.

Current storage is LocalFileStorage. Blob/Azurite and RabbitMQ application work remain planned until code/integration evidence exists. Do not copy legacy PostgreSQL/trigger/JWT/MinIO/result behavior into a recovery fix. From the repository root use `ACTIVE_backend_lalamog/solution/Lalamog.slnx`; from inside the backend use `solution/Lalamog.slnx` for the full solution.
